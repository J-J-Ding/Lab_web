正式开始之前，先统一以下规则，避免 Codex 在不同阶段自行设计出互相矛盾的权限系统。
身份	核心权限
ROOT	独立超级管理员，管理所有账号及系统安全设置
ADMIN	管理业务数据、普通用户及其角色
TEACHER	默认拥有与 ADMIN 相同的业务管理权限
STUDENT	管理自己的账号密码和个人信息
CUSTOMER	管理个人信息、提交简历、申请身份、查看审批状态

安全边界：ADMIN 和 TEACHER 可以管理 CUSTOMER、STUDENT、TEACHER，但不能修改 ROOT 或 ADMIN 的敏感权限和认证凭据；ADMIN 的权限提升、密码重置等敏感操作由 ROOT 负责。这是为了防止管理账号被间接接管。

一、项目总体建设目标

将现有以静态 HTML 为主的实验室网站，逐步升级为具备以下三大功能体系的综合平台。

1. 对外展示系统

面向社会公众、科研人员、合作单位和潜在团队成员。

主要功能：

实验室介绍

团队成员展示

科研论文与学术成果

科研项目

学科竞赛和荣誉奖励

技术博客

新闻动态

团队活动

毕业成员去向

实验室数据统计看板

所有公开内容原则上由数据库动态提供，不再依赖管理员逐个修改 HTML 文件。

2. 成员个人中心

面向实验室教师、学生和其他注册用户。

主要功能：

注册、登录及账号管理

个人资料维护

教育经历和研究方向

个人科研成果汇总

论文、项目和荣誉关联

内容创建与修改申请

投稿审核进度查询

历史投稿和修改记录

AI 文档导入及智能填充

成员维护一次资料，系统在适当权限和审核条件下自动同步到关联页面。

3. 团队管理系统

面向 ROOT、ADMIN、TEACHER 等具有管理权限的用户。

主要功能：

用户与角色管理

团队成员身份审核

内容投稿审核

已发布内容管理

科研成果关联管理

内容版本管理

数据统计与导出

操作审计和系统配置

二、核心业务设计原则

1. 一份内容，多处展示

论文、项目、活动等信息只保存一份权威业务记录。

例如：

一篇论文关联三位实验室成员，审核发布后自动出现在：

实验室官网论文栏目；

三位成员各自的个人主页；

实验室年度科研成果统计；

对应科研项目的成果列表（建立关联时）。

避免重复录入和数据不一致。

2. 内容与用户建立关联

系统应当区分：

创建人：最初提交内容的用户；

最后编辑人：最近修改内容的用户；

关联成员：真正参与论文、项目或活动的人员；

审核人：批准内容发布的管理人员。

一项内容可以关联多个成员，一个成员也可以关联多项内容。

外部合作者可以作为成果参与者记录，不要求其必须注册网站账号。

3. 编辑与发布分离

成员有权提交内容，不代表有权直接发布内容。

基本流程：

创建内容 → 保存草稿 → 提交审核 → 管理员审核 → 正式发布。

已发布内容发生修改时，需要生成新的待审核版本。

审核期间，官网继续展示原已发布版本；审核通过后统一更新。

4. 成员主页自动汇总

成员个人主页不应依赖重复手工填写科研成果。

系统根据成员与内容的关联关系自动汇总论文、项目、竞赛、活动等信息。

个人中心还应区分“已发布成果”“待审核内容”“我的投稿”“我参与的内容”。

5. 权限与隐私分离

用户角色决定管理权限，但不直接决定哪些个人资料可以公开。

每类资料需要明确公开范围，避免将账号邮箱、电话、简历等内部信息自动展示到公开网页。
