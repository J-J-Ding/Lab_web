# V11 全站布局、导航、轮播与搜索交互修正

状态：已获用户批准；实现及关键联调完成，后端候选待确认激活。分支：arc-update；基线：e72ee03。根据用户标注截图及10项反馈制定。当前仅新增本文档，尚未修改业务代码、运行配置或数据库。

## 1. 现状与目标

V10已有统一蓝色外观、公开API和直接保存。当前最大宽度固定1240px，在截图所示约2550px屏幕两侧留白过大；顶部快捷栏重复一级栏目；导航summary只展开、没有栏目入口；字号15px、箭头11px偏小。个人资料左侧是分组锚点，右侧教育经历却嵌在基本资料卡片中；团队工作区入口为松散链接，列表展示缺乏层次。

实测API不是全部不可用：`public/content/?q=科研`和`public/members/?q=丁俊`返回200，而单字`q=丁`返回400。全站搜索仅监听输入、没有明确提交行为，低于两字直接无响应；成员通用年份实际只查毕业年份，容易产生错误预期。后续按真实浏览器逐项检查搜索、筛选、重置、分页和结果状态，不能只改样式。

目标：用更充分的内容宽度、浅蓝侧背景、简化顶部、可点击栏目与页内分类、真实团队照片轮播、清晰分区表单，修正上述10项问题。沿用原生前端和现有DRF接口，不新增平行页面体系。

## 2. 推荐方案与取舍

采用“自适应宽内容区＋浅蓝渐变/轻量网格侧背景”。相较全屏拉伸长文本，此方案兼顾宽屏利用率与阅读；相较鼠标跟踪气泡，先避免干扰表单、额外动画和移动端耗电。背景不接收指针、不影响按钮点击；不启用大粒子库。

顶部采用“Logo/团队名 + 登录或个人中心/退出 + 搜索”一行，移除快捷栏及重复团队成员/资源链接。一级栏目直接可点击；有子类的栏目保留独立、清晰的展开按钮，与栏目链接分开。栏目内提供分类栏/侧栏，让点击一级标题也能直接进入默认内容。

照片轮播恢复真实团队风貌，不恢复旧首页虚构获奖/顶会文案。复用原有素材与代码思路，补上键盘、暂停及移动端控制。

## 4. API与筛选语义

- 复用`/api/public/content/`、`members/`、`graduates/`和`/api/content/items/`；公开查询始终只返回公开投影，不扫描旧HTML、不向匿名搜索混入团队或私有简历。
- 统一受限关键词长度为1–100字符，去首尾空格，保留参数白名单、分页与输入验证。全站结果可并列“内容/成员”，以姓名或标题显示，不泄露账号登录名。
- 内容列表的年份标签为对应内容业务年份；缺日期不会虚构归入某一年。
- 成员列表移除没有清晰语义的通用年份；毕业分类才显示“毕业年份”。毕业姓名搜索须同时支持，不能仍将搜索框禁用或传入不支持的q参数。
- 团队内容支持现有类型/标题/本人创建筛选，提供明确重置。Root账号/团队目录搜索若显示查询控件，必须有真实查询和结果反馈。
- 先通过浏览器网络响应确认每类控件是否提交正确参数、是否错误被静默吞掉，再修代码；不能把“没有匹配数据”当作筛选故障，也不能把请求200当作条件已经生效。
- 不调整V10身份权限、直接保存或公开规则；若需后端关键词/毕业搜索小改，镜像需单独重建并在获准更新服务后生效。

优先从当前公开活动/新闻的图片附件读取，复用受控`/api/public/assets/`和撤下门禁；首页聚合必要时增加有界slides数据，只返回公开图片和关联标题/链接。原活动图若尚未公开，先按现有文件/内容规则准备为可审核的候选素材，不将整个legacy_samples映射为静态资源，也不自动发布历史私人照片。只有一张可用图片时显示单张横幅，不制造重复照片“假轮播”；多张公开图片时自动轮播。

## 8. 风险与回退

CSS改动可能影响旧栏目与登录/管理页，抽查同一Header在深层URL和移动端的表现；导航链接与展开按钮不能互相拦截。放宽单字查询仍保持有界分页和输入上限，不做无界全库返回。照片公开必须继承业务撤下条件，轮播不得缓存仍可访问的私有副本。查询条件改变必须重置页码，旧请求响应不能覆盖新分类。

回退仅恢复本轮静态资源/兼容后端镜像，不回滚用户数据；无需数据库结构回退。不以移除筛选控件掩盖接口问题，不引入大量动画掩盖内容布局空洞。

## 9. 补充：恢复成果封面与完整内容渲染

用户补充：论文、竞赛等原有封面图消失，填写信息后公开页面仍显空荡。本项纳入V11同一轮实施，不能只修改颜色和留白。

### 已确认的代码问题与待定位项

- `frontend/js/content-list.js` 列表卡片目前只渲染标题、日期和摘要，完全没有读取API返回的assets绘制封面；即使已上传图片，列表也不会显示。
- `frontend/js/content-detail.js` 将每个详情字段拆成一个大标题，图片在正文末尾统一追加，缺少封面、元信息、正文和附件的清晰层次，少量字段时尤其显空。
- 当前编辑器把所有图片都当普通附件，没有明确“封面图”选择、预览和替换入口；重新编辑时附件也仅显示“已保存附件”。
- 公共API已有受控assets返回，但没有明确cover字段。旧网站存在各内容目录的封面文件，不能假定它们已经迁移、绑定和公开。
- “填写后没有渲染”仍需按具体字段逐项复现：检查保存请求、当前生效revision、公共JSON和DOM。不能把所有问题归因于未公开，也不能把保存成功提示等同于所有字段已持久化。

### 封面方案

1. 论文、项目、竞赛、新闻、文章和出版成果提供独立“封面图（选填）”区：选择图片→上传预览→保存，可替换/移除，不暴露asset ID。
2. 复用现有图片资产、RevisionAsset关系和position；用关系purpose标记cover，底层AssetFile仍使用image用途，避免新增平行文件存储。每个版本至多一张封面，由服务端校验；封面必须属于该版本合法图片集，不能引用他人私有文件。
3. 保存接口增加可选cover_asset，服务端统一保存封面关系，编辑读取返回cover及可预览的受控资源；未传字段时保留现有封面，明确null才移除。
4. 公共序列化增加可选cover对象，卡片、首页、个人成果、项目产出统一使用同一封面。兼容旧数据时优先显式cover，其次第一张合法公开图片；没有图片时采用紧凑类型标识或不占图位，不放空白大框、不重复Logo。
5. 列表按统一比例约16:10展示封面，详情页按原比例/合理最大高度展示，避免裁掉证书/图表关键信息；图片有alt、懒加载和加载失败降级。
6. 对旧封面生成只读盘点与匹配报告，优先按现有LegacyURLMap/导入记录的稳定内容映射恢复绑定，绝不凭相似标题或作者姓名猜测。恢复文件仍走安全校验/公开门禁；不批量发布历史草稿、不直接开放旧目录。已有图片不重复上传存储。

### 内容渲染方案

- 成果详情统一为“面包屑/标题 → 日期与作者等元信息 → 封面 → 摘要/正文 → 类型专属信息 → 关联项目与附件”。
- 论文集中展示作者、期刊/会议、年份、DOI和公开链接；竞赛集中展示赛事、奖项、级别、时间；项目集中展示编号、周期、状态等；已填写且允许公开的字段必须出现。
- 短字段使用紧凑信息网格/定义列表，不为每个字段单独堆大标题；正文保留换行，空字段不展示。标签枚举显示中文，数字0不能被真值判断误当空值。
- 成员卡片展示头像、姓名、身份、研究方向和简介的合理组合；个人成果、项目产出列表也复用图文卡片，不退回只有标题的链接堆积。
- PRIVATE/TEAM内容不能借封面URL泄露给匿名用户；Customer简历仍私有，项目经费等既有非公开字段不因“完整渲染”而公开。
- 不直接将用户正文作为任意HTML注入。保留安全文本和结构化渲染，不为恢复美观绕过XSS防护。
