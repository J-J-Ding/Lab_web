# V8：科研成果统计与团队数据看板

- 状态：待评审；技术依赖 V6 数据质量与公共选择器，默认在 V7 后实施，AI 不可用不阻塞统计开发。
- 目录 `/opt/Lab_web`，分支 `arc-update`；遵循[总体规划](V4-V9-后续开发总体规划与验收基线.md)。

## 1. 目标与范围

基于真实已发布业务数据自动汇总，分别提供公开成果展示和内部运营看板。沿用原生前端，可使用经评审的固定版轻量图表库或原生 SVG，并提供等价表格和可访问说明。不建设数据仓库、外部 BI、AI 预测或手工填写统计数字。

前提是 V6 的导入对账已完成；未清洗/不确定数据不强行填充，明确展示“年份未知/待核对”。不以虚构基线补齐漂亮图表。

## 2. 数据口径字典（先冻结后开发）

| 指标 | 粒度与去重 | 时间/范围 |
| --- | --- | --- |
| 团队人数 | distinct MemberProfile UUID | 按已发布public_member_status计ACTIVE在组/ALUMNI毕业；并检查即时privacy_gate；不按内部membership_status直接分组 |
| 教师/学生构成 | 按已发布成员类型分组 | 不按 UserRole 或账号数量计算 |
| 年度论文 | distinct ContentItem UUID（PAPER） | 已发布、未撤下；按发表日期年份，不按投稿或审核日期 |
| 项目数量 | distinct PROJECT UUID | 按立项年份；在研/结题单独状态，不按作者数放大 |
| 荣誉竞赛 | distinct AWARD UUID | 按获奖日期和类别；同奖多成员全站计一次 |
| 活动数量 | distinct ACTIVITY UUID | 按开始日期；跨年活动算开始年，日期缺失单列 |
| 成员成果 | 参与者链接的 distinct ContentItem UUID | 一项成果可在多位成员各计1；成员总和不等于全站唯一数 |
| 关联项目成果 | distinct 内容 UUID | 同论文可属多项目；跨项目汇总要声明可能重复 |
| 投稿/通过/驳回 | 按 Revision UUID 与 ReviewDecision 事件分别计 | 创建数、提交事件数、审核事件数不同；采用服务器时区转换 |
| 审核耗时 | 提交至最终审核的时间差 | 统计中位数/P95、样本量；撤回/未决不混入已审核样本 |

年份默认 Asia/Shanghai 的业务日历；过滤条件 begin/end 半开区间，跨时区测试覆盖边界。重发稿/版本变更不增加成果唯一数，撤下后公共统计同步减少。成员离组不删除既有成果；内部资格membership_status仅影响投稿资格，公开构成按审核后的MemberRevision字段及即时隐私gate统计，不能因后台改内部状态绕过审核；公开人数构成与历史年度人数不同，后者如没有有效状态变更历史不能推算。

年度对比在同指标同范围下计算；基期为0时增长率返回 null 并显示“无可比基数”，不是无穷或100%。未知日期纳入总量但不进入已知年份柱图，页面显示未知计数。

## 3. 公开、内部与导出权限

公共看板只用与公共 API 完全相同的已发布且可公开选择器；不显示注册用户数、待审/驳回数量、内部经费、个人联络或申请状态。内部管理看板 ROOT/ADMIN/TEACHER 可见运营数据，但不能借分组/导出枚举权限外的 ADMIN/ROOT 私密资料。

成员本人可见个人已发布与个人稿件数量；不能通过传 member_id 改看他人私有统计。小样本内部信息不能混进公共汇总；公共统计不得开放任意维度组合推断私密信息。

导出默认 UTF-8 CSV，字段白名单、行数≤10000；超出需更窄筛选或后续评审异步导出。Excel 公式前缀 = + - @ 及控制字符必须转义，不能把任意字符串直接作为公式。审计记录导出者、过滤条件摘要、字段、数量，不存完整导出数据；下载 no-store，临时文件按期限清理。公共导出如开放只含公开数据，内部导出另路由授权。

## 4. API、实现、页面与文件清单

| 方法/路径 | 输出 |
| --- | --- |
| GET `/api/public/stats/overview/` | 团队/成果公开总览、as_of、筛选回显、口径版本 |
| GET `/api/public/stats/annual/` | 年度论文/项目/奖励/活动序列、未知日期数量 |
| GET `/api/stats/me/` | 本人发布/投稿/参与汇总 |
| GET `/api/admin/stats/overview/` | 权限范围内稿件/审核/成员管理指标 |
| GET `/api/admin/stats/review/` | 审核数量/耗时、样本范围与定义 |
| GET `/api/admin/stats/export/` | 受控 CSV；下载被审计并限流 |

参数限定 year_from/year_to、kind、category 等白名单；单次最多20年，避免无限查询。结果带 `metric_version`、`as_of`、`filters`、`data`，缓存不能混淆不同权限范围。分页只用于明细，不把聚合数据按分页总数代替。

新增 `backend/apps/analytics/` 的 selectors、metrics、serializers、permissions、views/urls、exports、测试。初期基于 PostgreSQL ORM 聚合，避免先把整表拉到 Python；多对多使用 distinct 或去重子查询，专项测试 join 乘积放大。

初期不用单独统计事实表/定时手填数；缓存最长60秒，发布/撤下/隐私收紧通过 on_commit 失效，版本号控制避免旧统计残留。若实测需物化视图，先写刷新一致性和故障回退补充 spec 再上。

新增 `frontend/statistics.html`、`frontend/manage/statistics.html`、js/statistics.js、scoped CSS，个人中心增加本人汇总卡。图表有标题、单位、口径提示、空数据状态、筛选、下载与表格，移动端不只靠颜色区分，避免横向溢出。

新增 `docs/statistics-dictionary.md`、stats-api.md、`docs/V8-验收报告.md`；按实际查询计划添加迁移索引，不复制 content 数据建第二套权威成果库。

## 5. 实施顺序与强制测试

①负责人冻结口径字典；②构造可手算固定数据集和断言；③实现聚合/权限/导出；④做公开与内部页面；⑤性能与一致性；⑥完整回归与实际报告。

测试数据至少包括：三人共同论文一篇、两篇不同论文、论文三个版本、同论文关联两项目、不同年份/未知日期、撤下/草稿/待审成果、已毕业和未公开成员，以及同人多职责。

必须实际执行总体规划命令及 `python manage.py test apps.analytics --verbosity 2`，并验证：

- 全站共同论文计1，三位成员各计1；修改版本不增数；项目关联不放大全站论文量。
- 发布后更新、待审不变、撤下/隐私收紧后立即减少；公共列表与统计可逐项对账。
- 年界/闰年/上海时间、未知日期、基期0、非法/超大日期范围。
- CUSTOMER/STUDENT 无内部权限，参数篡改不扩大范围；导出字段和公式注入防护、限流、审计故障处理。
- 公开响应无内部投稿数量/敏感维度；匿名和内部缓存不能混用。
- 真浏览器筛选、表格/图表一致、下载、空态/错误、1440/390/320布局，V3–V7 既有流程全部回归。

性能目标（测试环境拟定）：1万内容/5万关联的合成隔离库中，常用统计 API 热缓存 P95≤500ms，冷查询≤2s，记录硬件、并发、样本及 EXPLAIN；达不到先优化索引/查询，不能拿单次最快结果冒称 P95。此处不是已测结果，也不等于生产 SLA。

## 6. 风险、回退与交付

主要风险是口径不一、JOIN 放大、动态隐私后缓存滞后和导出泄露。通过同一公共 selector、固定指标定义、手算样例、权限缓存分区与逐项对账约束。

看板故障可关闭入口、禁用缓存/退应用版本，不影响内容投稿与公开详情；不删除业务数据“修正统计”。交付指标字典、API、对账数据、实际性能/回归结果与查询索引说明。未完成的历史数据清洗列明影响，不能宣称统计完整准确。
