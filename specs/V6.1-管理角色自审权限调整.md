# V6.1 ROOT、ADMIN 与 TEACHER 自审权限调整

状态：2026-11-06 用户明确授权“root和teacher可以自审，root拥有所有权限，包括自己审核自己提交的内容”；随后用户补充“ADMIN 也要能够自审”，最终范围为三类管理者均允许自审，按此直接实施。工作目录 /opt/Lab_web，arc-update，不合并 main。

## 现状、目标及范围

V5/V6 将本版本编辑者/提交者全部禁止自审，导致 ROOT 导入示例后无法自行完成发布。按最新要求，ROOT（is_superuser）及业务角色 ADMIN、TEACHER 可以审核自己编辑、提交的内容、成员公开资料和本人身份申请。ADMIN 仅新增本人资料/申请的审批能力，不因此管理其他 ADMIN/ROOT 私密档案。ROOT 保持全局对象管理权限，普通角色不获得其他 ROOT/ADMIN 私密账号档案管理权。

自审采用相同提交→审核流程，保留审核理由、实际审核人/编辑人、审计日志、Session/CSRF、状态/版本/发布基线、署名确认、资产与本人公开授权校验。此变更不自动审核或发布已有28条示例，不修改账号密码、角色或现有数据。

## 方案与文件

在 workflow/permissions.py 集中声明可自审能力，content_services.py、member_services.py 的三种审批入口复用；views.py 的对象详情与三类审核任务 can_review 使用同一规则。调整内容编辑器和审核台的自审提示。修改 workflow API/编辑历史测试，新增角色矩阵、本人身份申请/公开资料、旧Session权限变更及审计验证；浏览器验证 ROOT/ADMIN/TEACHER 自审按钮和实际发布流程。更新 V5/V6 与工作流/API 文档说明新规则。

## 实施与验收

先写失败用例，再实现能力判断。隔离 PostgreSQL 执行 Django check、迁移漂移检查、完整 Django 和浏览器回归，明确 ROOT/ADMIN/TEACHER 成功、普通账号拒绝，不能用请求参数伪造权限。现有相反断言按新的明确需求改为矩阵断言，不删除失败测试。

测试通过后构建独立候选镜像，备份数据库/媒体，再更新当前服务器后端和默认 Compose 镜像；只读验证健康与审核权限，不在生产创建测试账号或自动发布示例。本次无模型变化，无需新增迁移。保留用户 Dockerfile/README 改动和旧镜像。

## 风险与回退

允许自审降低人员分离要求，这是用户明确选择；所有操作仍记录真实账号和审核理由。风险主要是服务与任务界面判断不一致，用共享规则与真实浏览器用例防止。回退旧镜像可恢复禁止自审规则，保留已形成的审核/版本记录，不倒改历史或恢复数据库覆盖现有内容。
