# V17 Root 首页轮播图片管理

状态：用户已批准实施并追加账号注销、统一默认密码、筛选与用户名检查。已实现并同步运行版本，验证见 docs/V17-首页轮播与账号管理实施验证.md。

## 现状

- 首页轮播自动取新闻／活动封面，无符合条件的内容时使用实验室Logo占位。
- Root没有独立轮播管理入口，无法直接配置首页图片与文字。
- 当前图片上传、资产检查、Root身份判断和首页会话权限接口可复用。

## 目标与范围

在“团队管理”增加仅Root可访问的“首页轮播管理”，直接上传、替换、排序、启停和删除轮播项，不要求创建新闻／活动。

- 每项包含图片（必填）、标题（可留空）、副标题（可留空）、显示顺序、启用状态。
- 保留当前5秒切换、淡入淡出、居中文字与蒙版、底部居中小点；“了解实验室”仍滚动到首页概述。
- 管理列表每页最多5项；提供图片缩略图及预览，保存后立即生效。
- 图片支持PNG/JPG/WebP，单张不超过5 MiB；横向铺满、按比例缩放，高度超过可用屏幕时截断。
- 不扩大Teacher、Student、访客的管理权限；不改已有新闻／活动内容与封面。

## 方案

采用独立轮播配置及管理页。继续依附新闻封面不能满足独立修改需求；直接改静态文件缺少后台入口与审计，因此不采用。

### 存储与接口

- 新增轮播配置：显式模式`AUTO`或`MANUAL`、锁版本；轮播项包含图片资产、标题、副标题、顺序、启用状态、删除时间及修改时间。
- 初始模式AUTO保持现有首页行为。Root选择MANUAL后只使用管理列表中的启用项，不再自动混入新闻封面；没有启用项时使用Logo占位，页面明确提示这一结果。可切回AUTO。
- Root管理接口服务端强制检查活跃Root账号，并执行CSRF及锁版本校验；普通用户即使手写请求也不能修改。
- 管理保存、排序、启停、删除与模式变更记录审计。删除只解除有效轮播引用，保留审计；不立即物理删除仍被其他内容引用的图片。
- 图片须本人上传或该轮播原有合法图片，且用途为image、扫描通过、未过期、无删除标记。保存成功后取消未保存上传的过期时间；文件清理增加轮播有效引用检查。
- 首页接口仅输出MANUAL模式下启用且未删除项的安全字段；公开图片接口仅对这些有效引用放行。未启用或已删除图片若无其他公开引用，匿名不能访问。
- 轮播管理使用独立业务模型，不作为科研成果，不计入成果统计或成员关联。

### 页面

- Root在“团队管理 → 首页轮播管理”选择自动／手动模式。
- 新增项或编辑项时可直接上传图片、查看缩略图、填写标题及副标题，设置顺序与启用状态。
- 保存按钮明确提示结果；图片未上传完时禁止保存，失败保留输入；切换模式前说明实际首页来源。
- 删除需要确认；关闭启用可以临时撤下而保留配置。列表分页、搜索无需改变现有账号管理。
- 标题留空不渲染空标题；当前Logo占位文字保持现有规则。管理数据不暴露给非Root。

## 风险与回退

- 手动模式启用图片就是对外展示授权，界面明确提示，不复用私有简历、头像或内部附件。
- 图片删除只撤下轮播引用，避免误删被成果等其他记录使用的文件；清理必须检查有效引用。
- 模式切回AUTO可恢复现有新闻／活动来源。数据库采用增量迁移，回退保留配置和文件，不删除新表恢复旧应用。
- 上线前备份数据库与私有文件；不更换Nginx、域名、SMTP或其他系统配置。
