## 3. 页面与交互设计

沿用 style.css 的字体、色彩变量、圆角、阴影、logo 和导航布局；新增样式集中在 frontend/css/auth.css，使用 auth- 前缀及页面容器作用域。原则上不修改 style.css；如确需全局样式变更且会影响原页面，先更新本 spec 再评审。

| 页面 | 内容 | 成功行为 | 错误行为 |
| --- | --- | --- | --- |
| register.html | 用户名、密码、确认密码；固定提示“新账号默认身份：CUSTOMER（访客）”；已有账号登录链接 | 显示注册成功及前往登录按钮，不自动登录、不携带密码跳转 | 显示重复用户名、弱密码、必填/格式及确认密码不一致提示 |
| login.html | 用户名、密码、注册链接 | GET me 确认会话有效后进入 profile.html | 凭据错误统一提示，不区分不存在、错误密码和禁用账号；429 显示合理重试时间 |
| profile.html | 当前账号、身份、姓名/email；本人资料编辑表单；旧密码/新密码/确认新密码表单；退出按钮 | PATCH 资料后重新 GET me 展示数据库结果；改密后清空密码框并提示成功，保持当前会话 | 未登录跳转登录；资料/密码校验错误就地提示；接口暂不可用显示重试状态 |

用户名和身份只读；个人资料只提交 first_name、last_name、email。role、is_staff、is_superuser 不提供可编辑控件，不进入任何提交 payload。

身份显示优先判断 is_superuser：ROOT（超级管理员）；否则按 ADMIN（管理员）、TEACHER（教师）、STUDENT（学生）、CUSTOMER（访客）显示后端真实角色。未知值显示中性的未知身份，不猜测权限。注册提示不代替读取后端实际身份。

注册和登录页面建议使用最大宽度约 480px 的单列表单；个人中心最大约 960px，桌面可分摘要/编辑区域，移动端单列。沿用 768px 断点，控件和按钮适应窄屏，不出现水平滚动或被固定高度裁切。

每个控件有明确 label、autocomplete 和输入类型；密码使用 password/current-password/new-password，确认密码不发送后端。状态区使用 aria-live，错误关联到输入控件，保留键盘焦点和可见 focus 样式。提交期间防重复点击并显示进度，失败后恢复操作。

登录成功固定跳转站内 profile.html，不支持未校验的 next/外部跳转参数。注册成功可跳转 login.html?registered=1，仅传非敏感成功标记，不将账号或密码写到 URL。

## 4. 统一导航与嵌套路径

- 原左右菜单、栏目、logo、激活态、搜索初始化及移动端换行保留。
- 模板新增独立账号入口区域：匿名显示“登录 / 注册”；已登录显示“个人中心 / 退出登录”。退出是 button，通过 POST 调用接口，不能用 GET 链接退出。
- 初次查询身份期间显示中性加载状态，避免把尚未确认的登录状态当成匿名。认证服务故障不能阻断原导航、栏目或 logo 加载。
- 新增入口使用 data-original-path 或同等稳定标记，复用现有相对路径计算；从首页、栏目列表、深层详情均能正确打开根目录认证页面，不拼出 `/data/.../login.html`。
- navbar-loader.js 在模板插入及原路径修正后，按页面根目录解析路径，幂等加载 auth.js 和 auth.css，并调用 `window.LabAuth.initNavigation(navbarContainer)`。
- auth.js 也可由新页面正常引用；脚本/样式只加载一次，初始化可重复调用而不重复绑定事件。模板中的 script 不依赖 innerHTML 自动执行。
- 表单初始化与异步导航初始化独立，使用共享的当前用户读取 Promise，避免脚本先后次序导致表单不工作或导航始终显示匿名。
- 新样式只影响 auth- 表单和账号入口，专门保证 hidden 区域不被现有菜单 display 规则重新显示。旧链接路径转换不重复执行，新入口不得改变原有栏目路径。

退出成功后立即清空当前页面账号状态：公开页面保留当前网址并显示匿名导航；个人中心使用 location.replace 进入登录页。后端失败时不宣称已退出，给出重试提示并重新读取实际会话状态。

## 5. Fetch、CSRF 和身份状态

共享 API helper 使用相对同源 `/api/auth/`、`credentials: 'same-origin'`、`cache: 'no-store'`。不硬编码公网 IP、测试端口或跨源后端 URL，不通过放开 CORS 解决接口路径问题。

流程：

1. 页面/首次写操作先 GET /api/auth/csrf/，确认响应成功且能够读取 csrftoken Cookie。
2. 每次 POST/PATCH 在发送当下重新读取 Cookie，设置 X-CSRFToken 和 JSON Content-Type；不长期缓存 token。
3. 注册只提交 username、password；首次身份必须由后端产生。201 后显示引导登录，不伪造已登录状态。
4. 登录成功后读取轮换后的 Cookie；GET /api/auth/me/ 确认 Session 和真实身份，再更新导航与进入个人中心。
5. 每次页面加载/刷新使用 me 查询，身份缓存仅存在当前页面内存，不使用 localStorage/sessionStorage 存凭据或身份授权结论。
6. 修改资料后再次 GET me；改密发送 old_password、new_password，成功清空密码输入并查询会话。旧密码失效由后端实际测试验证。
7. 退出 POST 成功后清空 UI 并重新确认匿名状态。个人中心未登录/会话失效时不展示历史资料。

403 处理必须分场景：me 的 403 表示无有效会话；登录/注册写请求的 403 可能是 CSRF 失败，不能显示为“密码错误”。已登录写请求收到 403 后重新 GET me：若仍登录则提示安全验证失效，刷新 CSRF 后让用户主动重试；若匿名则引导重新登录。不能未经确认自动重放注册、改密或资料修改请求。

400 字段错误转为友好提示；429 展示 Retry-After；404/HTML 响应、5xx、超时和网络错误显示服务异常，不能误判为匿名登录成功或显示原始服务器 HTML。响应数据和错误消息使用 textContent/安全 DOM，不将用户名、姓名、email 或接口错误插入 innerHTML。

使用有限请求超时（建议 15 秒）。网络中断可能发生在服务器已完成操作之后，不能自动重复非幂等提交；提示用户确认结果或重新读取状态。

## 6. 安全、缓存与页面生命周期

- 不保存密码或 Session 到 localStorage、sessionStorage、URL、日志、HTML 属性或测试报告；不尝试读取 HttpOnly sessionid。
- 密码字段只在提交期间读取，不写回接口响应，不把密码保存到共享状态；成功、退出和 pagehide 时清空密码输入。
- profile 的资料区域初始隐藏，me 成功后才显示；pagehide 清空/隐藏敏感资料，pageshow（含浏览器返回缓存）与重新获得页面可见性时重新验证会话，避免退出后浏览器后退展示旧资料。
- 其他标签页退出后，重新聚焦/恢复个人中心触发身份检查；状态确认期间隐藏资料并禁用写操作，不依赖本地存储的已登录标志。
- 真正的用户权限始终由 V2 后端验证；浏览器隐藏或禁用字段仅为交互规则。篡改 role 的写请求仍必须被后端拒绝。
- 不修改 Session、CSRF、密码强度或登录限流的后端策略，不为前端测试关闭 CSRF。
- 当前没有 HTTPS 验收，只使用新生成的隔离测试账号，在回环测试环境操作。生产 ROOT 或真实账号密码不得用于浏览器测试。
