# V10 使用与部署说明

## 代码与运行服务是两件事

V10源码在当前 `/opt/Lab_web` 的 `arc-update` 分支；系统Nginx读取此目录的静态页面，所以页面变化会立即可见。运行中的后端镜像仍可能是V7–V9版本，`docker compose up`不会自动把源码装进已经构建的镜像。

2026-11-06实际检查：Nginx首页已是V10，运行后端为 `lab-web-backend:v789-20261106`，健康接口200，但 `/api/public/home/` 返回404。因此当前原服务不是完整V10联调环境。本次开发在隔离数据库和临时后端进行了联调，不自动替换线上服务、不合并main。

## 入口与新规则

- `/index.html`：固定科技蓝首页，读取 `/api/public/home/`；不会读取自由编辑的home正文控制布局。
- `/profile.html`：姓名、简介、研究方向、教育、头像、公开范围；选填可留空。本人另可修改联系邮箱和密码。
- `/workspace.html`：团队内容列表；`/content-editor.html` 直接编辑保存，无提交审核。
- `/resume.html`：私有简历，只本人与Root可访问，不参与官网聚合。
- `/manage/index.html`：Teacher/Root管理团队业务资料；仅Root显示账号身份、密码和启停管理。
- `/resources.html`、`/contact.html`：资源共享与受控联系页面；旧九栏目、成员和成果URL保留。
- `/ai-import.html`：候选选择后转入结构化表单，用户核对后正常保存；AI默认关闭，缺有效预算/价格时正常提示不可用，不影响手工填写。没有执行额外真实付费请求。

Root使用is_superuser；业务TEACHER显示Teacher、STUDENT显示Student、CUSTOMER显示Customer。旧ADMIN迁移为TEACHER并记录审计。Teacher不能管理他人密码/角色或Customer私有资料。作者从注册Teacher/Student姓名目录选择，关联不授编辑权。默认PUBLIC并在保存前明确提示，也可改TEAM；Customer资料和简历始终私有。

## 主要API

- `GET /api/public/home/`：公开计数、研究方向、新闻、论文、项目、竞赛、成员、资源。
- `GET/PATCH /api/members/me/profile/`、`/api/members/{profile_id}/profile/`：本人/有权限目标业务资料。
- `GET /api/members/directory/?q=姓名&page=1&page_size=100`：内部姓名目录，Customer/匿名拒绝。
- `GET/POST /api/content/items/`、`GET/PATCH /api/content/items/{id}/`：直接保存，类型/标题最小必填；修改必须传lock_version，版本仅由客户端维护。
- 内容保存字段：`kind`（新建）、`title`、`summary`、typed `detail`、`authors`（账号ID数组）、`authors_ordered`、`assets`、`project_links`、`visibility_scope`。`featured`仅Teacher/Root可写。
- `GET /api/content/items/{id}/history/`、`POST /api/content/items/{id}/restore/`：恢复请求 `{lock_version,source_revision}`，生成新历史。
- 本人资料对应 `members/me/history/` 和 `members/me/restore/`；管理目标使用 `members/{profile_id}/history/`、`restore/`。
- `POST /api/content/items/{id}/grants/`：Teacher/Root授予/撤回编辑权，字段 `{lock_version,user_id,can_edit,revoke}`。
- `GET/POST /api/members/me/resumes/`、`GET/PATCH /api/members/me/resumes/{id}/`：私有简历，字段title/intention/introduction/asset，修改携带lock_version。
- 原accounts账号管理API路径保留，但统一Root限定。原提交、审核、贡献确认等写入口返回410，历史表不删。

所有写请求保留Session/CSRF：先GET `/api/auth/csrf/`，携带Cookie及当前 `X-CSRFToken`；登录后读取轮换token。不得在localStorage保存密码、Session或AI密钥。

## 获准发布后的更新命令（本次未对生产执行）

先确认具体提交及维护窗口。以下操作会改变运行服务和数据库，不代表代码提交已获上线授权。

```bash
cd /opt/Lab_web
git switch arc-update
git pull --ff-only origin arc-update
# 将backend/worker/migrate统一设为本次独立标签，例如lab-web-backend:v10-<短SHA>。
# 不覆盖现有运行镜像的标签；可用本地release override指定三服务的image。
sudo docker compose -f docker-compose.yml -f <V10-release.yml> build backend
sudo docker compose -f docker-compose.yml -f <V10-release.yml> --profile maintenance run --rm --no-deps migrate python manage.py check
sudo docker compose -f docker-compose.yml -f <V10-release.yml> --profile maintenance run --rm --no-deps migrate python manage.py migrate --plan
bash deploy/scripts/backup.sh --output /opt/lab-web-backups/<新的V10批次>
sudo docker compose stop backend
sudo docker compose -f docker-compose.yml -f <V10-release.yml> --profile maintenance run --rm --no-deps migrate
# 为新表补运行角色权限；密码从私有env_file传LAB_RUNTIME_DB_USER/PASSWORD，不写命令行或Git。
sudo docker compose -f docker-compose.yml -f <V10-release.yml> -f <私有角色授权override.yml> --profile maintenance run --rm --no-deps migrate python manage.py provision_runtime_role
sudo docker compose -f docker-compose.yml -f <V10-release.yml> up -d --no-deps --no-build --wait backend
curl --fail http://127.0.0.1:8000/api/health/
curl --fail http://127.0.0.1:8000/api/public/home/
sudo docker compose exec -T backend python manage.py migrate --check
```

迁移范围：accounts.0003角色归并/会话失效、assets.0005 resume用途、content.0007–0009可见性/精选/contact/状态约束、members.0006 Customer资料/Resume。旧草稿保留且不自动公开；公开生效版本、历史账号主键、密码哈希、旧URL与审计历史不删除。运行角色不得提升为超级用户来解决新表权限。

回退记录旧镜像ID与静态资源提交；新schema和数据保留，回退代码必须继续收紧Teacher安全权限。不要恢复旧账号管理逻辑、反向删除迁移数据或执行down --volumes。最新未部署代码不能宣称已在原网站联调通过。
