# V5 工作流与安全边界

## 版本和发布

DRAFT 可编辑，提交后变成不可修改的 SUBMITTED 快照。有审核权限的管理者可驳回或批准；批准与公开指针更新在同一数据库事务完成。REJECTED/WITHDRAWN 只能克隆成新编号草稿；历史版本不覆盖。旧发布版 A 在 B 待审期间保持公开。并发更新检查 lock_version，审批还检查 base_published_revision；不自动合并冲突。

按用户最新要求，ROOT（is_superuser）、ADMIN、TEACHER 均可审核本人编辑或提交的版本；STUDENT/CUSTOMER 无审核权限。编辑历史、提交、审批、确认、公开授权、管理动作与审计使用独立追加记录，迁移回填已有编辑依据，不伪造历史批准。last_edited_by 只由实际编辑更新，不被审核者或提交动作覆盖。事务中审计失败会回滚业务状态和发布指针。

撤回待审版不撤下旧公开版；归档阻止继续投稿但可保留公开；撤下停止公开，必须记录理由。恢复归档允许继续编辑；恢复公开仍需新版本审核。管理理由通过 moderation-history 留存，不依赖客户端提示。

## 账号、成员与署名

账号角色、成员身份类型、贡献者署名是不同对象。关联署名不会自动绑定账号或授予私稿编辑权。创建者和显式协作授权控制编辑；撤销权限在服务端生效。署名确认只暴露必要摘要；新版本重新确认，争议阻止发布。管理者可凭证据代确认，但必须记录理由。已发布的署名纠错通过新版本处理，隐私紧急情况先撤下。

身份认领锁定账号、申请和两份档案，禁止自动按姓名绑定。临时档案有成果、贡献者关联或发布记录时拒绝自动合并。无冲突时保留临时稿和合并来源，目标字段只按审核者显式选择写入候选稿，不覆盖已发布资料。

身份审批不会授予 TEACHER/ADMIN/ROOT；CUSTOMER 审批后可成为 STUDENT。独立用户角色管理保持 V2 已获授权的规则，详见认证文档。总体规划中“ROOT 单独授予 TEACHER”的建议不替代用户明确要求的 V2 普通角色管理能力。

ROOT 可管理全部成员私密档案和申请并可自审；ADMIN 可审核本人资料/申请，不能接管其他 ADMIN/ROOT 私密档案；TEACHER 自审限本人及其原有普通账号管理范围。一般业务内容仍按业务对象权限审核，不把高权限作者的文章等同私密账号档案。自审仍走提交、版本校验、公开授权校验和审计流程。

## 公开授权与会话

资料稿记录公开授权及 privacy_version。本人可以立即收紧公开、联系方式、教育、校友展示范围；收紧更新隐私版本，使先前待审授权失效。恢复须本人新授权、重新提交和有权管理者审核，不直接 PATCH 恢复。服务在锁内重新读取账号角色、禁用状态及 Session 密码哈希，密码重置后等待中的旧 Session 也不能继续写入。

前端复用 Session/CSRF，登录后读取轮换 Token。保存前不允许提交未保存输入；冲突保留输入并要求人工处理。页面退出或会话变化会清除私密内容；页面恢复重新核验。界面隐藏按钮不能替代服务器权限校验。

## 文件与保留

头像经 Pillow 解码、限制单帧/一千万像素并重编码为 PNG；PDF 经 pypdf 严格解析，限制 1–100 页和对象遍历规模，拒绝动作、脚本、表单、嵌入内容等再重写。检查子进程限制内存 256MiB、CPU 5 秒、父进程超时 8 秒和输入输出大小；不传入数据库或 Django 密钥环境变量。这是受限结构检查与清洗，不是完整杀毒或完整操作系统沙箱。

所有文件进入私有卷，随机路径、0600 权限、受控下载，不配置 Nginx 媒体目录。失败验证不产生可用资产，事务失败清除落盘文件。默认 30 天过期；清理保留元数据并跳过仍被活动/已发布资料引用的头像。`python manage.py cleanup_private_assets` 默认仅预览；实际删除必须使用 `--apply`，本次未启用定时任务。

V5 不实现公共官网动态化、通用附件、AI、简历审核、看板；后续阶段必须继续使用公开选择器及隐私门禁，不能直接查询草稿对外展示。
