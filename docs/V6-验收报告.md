## 失败修复与独立审阅

公共 API、上传、导入和新增页面均先有实际 RED 再实现。额外回归发现导入后续文件失败会遗留先前字节、Unicode 数字参数导致 500、长英文旧 URL 被过短上限误拒绝，均修复并再次执行测试。损坏/伪装/超限文件、ZIP 路径穿越/外部关系/宏/压缩预算、跨用户和 CSRF 拒绝均保留断言。另用结构合法、展开比超过 100 倍的压缩 DOCX 实际执行校验并确认拒绝。

独立审阅发现 4 项 Important，无 Critical/Minor；均新增失败复现并修复：

1. 非空成员/项目成果列表误链式调用 DOM append，现由真实浏览器验证。
2. 协作者无法保留他人的既有附件，现允许保留合法现有引用、新增仍查所有权。
3. 独立审核者无法下载待审附件，现按内容可见性授权并提供下载入口。
4. 不同源记录共用旧 URL 会覆盖草稿，现预先拒绝清单别名冲突、跨批次检查来源身份。

## 实施取舍、未验证与后续

- 公共响应统一 no-store：避免隐私撤回 TTL 泄露，代价是每次请求数据库；性能需求增大再评审缓存。
- 正文先纯文本安全渲染：代价是暂不支持复杂 Markdown/HTML 排版，不执行任意标记。
- 原示例移出静态目录：按用户追加授权执行；旧媒体直接 URL 不再继续公开，获准使用的媒体须经校验和版本审批；原“只做关闭开关、等上线才切静态页”的初始决定已被此次明确授权替代。
- 文件机制为限资源解析与清洗，不是完整病毒扫描；删除请求不立即物理删除历史引用文件。

正式 backend/db 容器仍为原容器和健康状态，未执行生产数据库迁移、示例导入、后端镜像替换、Nginx 修改或 main 合并。正式后端仍旧版本，新的公共 API 尚未上线；当前静态页面源码已更换，完整动态展示需后续批准部署并发布资料。

尚未验证：真实 ECS V6 镜像部署、生产数据迁移、Nginx 21m 上传上限、真实域名 HTTPS 和生产压测。本次没有调用 AI；V7 AI/V8 看板/V9 上线治理不在范围。现有 `.env` 保持忽略及 0600，未写入仓库；用户 Dockerfile 与 README 改动保留且不纳入提交。
