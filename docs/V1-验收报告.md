## 失败与修复记录

1. Docker Hub 直连超时；经已有本地代理能够访问。为 Docker daemon 增加 `/etc/systemd/system/docker.service.d/lab-web-proxy.conf`；构建客户端另传代理。pip 大包直连下载缓慢，使用临时构建覆盖让构建步骤通过宿主机代理下载。该 host 网络仅用于构建，未用于运行服务，代理未写入镜像、Compose 或真实应用环境。
2. TDD RED：在自定义 User 尚无 role、尚未注册 health 路由时运行 12 项测试，观察到 16 个失败与 3 个缺失字段错误（含子测试）。实现 role、约束及接口后 12/12 通过。用于 RED 的未提交初始迁移仅用于已销毁的测试库，最终迁移在第一次操作持久主库前重新生成，未删除任何现有业务数据。
3. 首轮部署验收：容器内部 health 200，但宿主机 curl 退出 7。实际 inspect 显示端口绑定声明存在、有效映射却为 null，ss 没有 8000 监听。原因是后端只连接 Docker internal 网络。修复后端同时连接独立 host_access 桥接网络与数据库内部网络；db 仍只连接内部网络。重跑确认回环端口、真实 HTTP、停库与恢复均正常。
4. 首轮 Gunicorn 日志存在 `/home/app` 权限错误，实际 home 可写检查退出 1。Dockerfile 改为创建 app home；重建后非 root/home 检查通过，控制 socket 正常，日志无 ERROR。

最后一轮运行验收程序整体退出 0。没有遗留失败测试。上述网络连接与 home 修复经过实际重现和验证，未以静态配置检查代替运行结果。
