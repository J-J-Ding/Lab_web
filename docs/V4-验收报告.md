## 1. 实现结果

新增members/content/assets/workflow四个模块、27张业务表：assets1、members10、content15、workflow1。保留accounts.User、既有迁移、Session、角色与认证审计；不改变ROOT/is_superuser与四业务角色的规则。

成员档案与账号独立、一对一可空绑定；成员公开身份位于资料版本，内部资格与即时隐私门留在档案。教育/研究方向/去向按版本保存；私密联系方式分表。ResearchArea规范词不可原地改名，防止历史版本间接变化；公开slug必须唯一占位并属于本档案。

八类内容使用独立明细表。ContentItem提供稳定UUID和类型（创建后不可变），ContentRevision保存版本；发布和工作指针不能越对象引用，内容与成员通过规范Contributor及版本贡献关系关联，保留历史署名。DOI/项目号/ISBN/PAGE按规范唯一占位，清空草稿标识不释放原占位；相似标题只提示，不自动合并。

PostgreSQL延迟图约束检查每版本恰有一种正确明细、版本/状态归属、项目目标和贡献职责；BEFORE触发器保护非DRAFT快照及子表，直接SQL同样无法绕过。写服务重查当前账号权限并锁定对象，乐观版本号防止过期写覆盖，业务审计失败整笔回滚。

V4不提供无审核发布接口。已发布测试样本只在隔离库以事务建立，供验证旧版保持、关系查询和私密字段过滤；真实审核流程由V5实现。

## 2. API及请求示例

详细契约、Cookie/CSRF和嵌套资料示例见 [member-api.md](member-api.md)。新增：

- GET/POST/PATCH `/api/members/me/draft/`：只读查询、幂等初始化和版本锁更新。
- GET `/api/members/me/overview/`：本人档案/版本状态与公开成果数量。
- GET `/api/content/participations/`：本人关联已发布未撤下成果，支持kind与分页。

PATCH示例（必须同时携带有效Session与最新X-CSRFToken）：

```json
{"lock_version":0,"display_name":"示例成员","bio":"智能控制研究","research_areas":["智能控制"]}
```

role、绑定账号、成员类型/状态、发布指针、创建人等不可经请求修改；CUSTOMER创建本人资料不获得投稿或管理权。无登录403、非法输入400、无草稿PATCH404、版本冲突409、审计/数据库故障脱敏503。API错误体沿用既有认证接口约定；本版本没有重写现有账户API。
